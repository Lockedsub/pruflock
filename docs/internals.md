# How PrufLock works

The details behind the badge, for contributors and the curious. Everyday use is covered in the [README](../README.md).

## Talking to ChastityTracker

The badge uses the same endpoints and session as the web app, logged in as the wearer.

| Call | What for |
|---|---|
| `GET /api/auth/csrf`, then `POST /api/auth/callback/credentials` | Login. Returns the Auth.js session cookie `__Secure-authjs.session-token`. |
| `GET /api/heartbeat` | Every poll. `pendingSig` holds `k:<ids of pending inspections>` and `l:1`/`l:0` (locked). `sessionUserId: null` means the session expired. |
| `GET /api/kontrollen/open` | When something is pending: `{ inspections: [{ id, code, deadline, … }] }`, most urgent first. `code: null` means no code is needed. Needs ChastityTracker 6.4.0 or newer. |
| `GET /api/auth/session` | After a login, on a button press, and when no timezone is known yet: `user.name` and `user.timezone`. |

- **Session cookie:** kept in RTC memory and in NVS (written at most every 12 h), so the badge rarely logs in.
- **Wrong password:** one attempt, then the badge waits for a reconfiguration or a button press, because failed logins count towards the app's account lockout.
- **Timezone:** the account's IANA zone (e.g. `Europe/Zurich`) is mapped to a POSIX TZ rule through `src/tz_db.h`, which `tools/make_tz.py` generates from the system's zoneinfo. Deadlines arrive in UTC, so the zone only affects the "due 15:30" label. An unknown zone falls back to UTC.
- **TLS:** certificates are checked against Mozilla's root CA list built into the Arduino-ESP32 core (`useBuiltinCACertBundle()` in `src/http.cpp`). A private CA or a self-signed certificate is not supported.
- **API contract:** the field names of `/api/kontrollen/open` are pinned by a test in the app (`src/app/api/kontrollen/open/route.test.ts`). If the heartbeat format changes, adjust `TrackerClient::heartbeat` in `src/tracker.cpp`.

## Setup portal

Phones show a "log in to this network" sheet when they detect a captive portal. The badge provides one with as little waiting as possible:

- It scans for networks first (they become suggestions in the form). From then on, the radio runs as an access point only, with power save off, so the phone's first packets don't get lost.
- A small DNS server answers every A query with `192.168.4.1` and gives empty answers to AAAA/HTTPS queries.
- Requests for any other host, including the connectivity checks (`/hotspot-detect.html`, `/generate_204`, `/connecttest.txt`), get a `302` to `http://192.168.4.1/`. That is the clearest "login required" signal.
- The DHCP server also sends option 114 (RFC 8910) with the portal URL, which can help iOS open the sheet sooner (`PORTAL_DHCP_114` in `src/config.h`).
- The web server in `src/portal.cpp` serves up to 4 connections and drops idle ones after 1 s. The stock Arduino `WebServer` handles one at a time, and a phone's spare pre-opened connection would block its connectivity check.
- iOS still shows the sheet only after about 45 s, on a fixed timer. So 5 s after a phone joins without opening the page, the display says to open 192.168.4.1 in the browser.

The serial log timestamps each step from the moment the access point is up (`[portal] +<ms> station joined`, `lease …`, `dns …`, `GET …`).

## Wi-Fi

The badge tries, in order: the access point that worked last time, then the strongest configured network found by a scan. If neither works, it asks for each unseen network by name, taking turns, for 20 s (45 s after a button press). That last step wakes an idle iPhone hotspot, which stops broadcasting its name until a device asks for it. Without Wi-Fi, the sleep time doubles from 60 s up to 10 min.

## Hardware

- **Wake-up:** button A = GPIO0 (`ext0`), button B = GPIO35 (`ext1`, external pull-up), plus a timer: 60 s normally, up to 10 min without Wi-Fi, 15 min after a rejected login.
- **Vibration motor:** GPIO27 through a transistor, held LOW during deep sleep.
- **Battery:** read on GPIO34 (divided by 2, enabled through GPIO14). Above 4.35 V counts as USB power.
- **Fonts:** TFT_eSPI's built-in fonts are ASCII-only, so the text uses Liberation Sans Bold at 16 and 24 px with umlauts (`src/fonts.h`, generated by `tools/make_fonts.swift`). The code uses TFT_eSPI's 7-segment font; codes longer than 7 characters use its font 4, doubled.

## Battery life (estimates)

- Idle: one wake per minute, about 3–5 s with Wi-Fi and TLS.
- A code on screen: backlight and Wi-Fi stay on.
- No known network in range: about 25 s of radio time per wake.
